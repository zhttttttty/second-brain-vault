# 内容是否值得进入知识库

## 来源

改编自 YC思维与学习《把 Obsidian 当做知识库，浪费了它 90% 的能力》。原文强调少囤积、重理解、经验和连接；本清单结合当前 Vault 的建卡门槛与来源分层规则进行了收敛。

---

## 清单内容

### 判断长期价值

- [ ] 它是否服务当前重点、活跃项目或一个长期问题？
- [ ] 我能否说出未来什么判断、行动或创作场景会调用它？
- [ ] 它是否包含通用回答难以替代的个人经验、一手证据、独特判断或关键表达？
- [ ] 它是否补充、修正或挑战了已有理解，而不只是换一种说法？
- [ ] 原文本身是否具有未来引用、核验、离线保存或防失效价值？

### 检查重复与连接

- [ ] 已搜索 `03_Knowledge/INDEX.md`、相关 Topic 和卡片，确认没有同义页面？
- [ ] 如果已有页面，是否应更新旧页而不是新建？
- [ ] 能否说明它与现有知识的具体关系，例如因果、层次、对比、演化或依赖？
- [ ] 若无法建立有意义的关系，它是否仍因独特证据或个人经验而值得独立保存？

### 决定唯一落点

- [ ] 通用且重复 → 不进入正式知识区。
- [ ] 补充已有认识 → 更新现有卡片或 Topic。
- [ ] 独立、稳定且可复用 → 创建一张原子卡片。
- [ ] 服务明确结果或下一步 → 写入项目或任务。
- [ ] 只有原始证据价值 → 保留在 References，不复制成知识卡片。
- [ ] 暂时无法判断 → 留在 Inbox，并写明再次判断的条件。

---

## 使用场景

- 处理一篇新剪藏时，先用本清单决定是否产生长期知识。
- 准备创建卡片时，用它检查重复、调用场景和关系语义。
- 清理 Inbox 时，用它区分“保留原始证据”和“沉淀自己的理解”。

---

## 关键提醒

1. “AI 能回答”不等于“不值得保存”；重要的是内容是否给当前知识体系带来真实增量。
2. “从未回看”不等于“没有价值”；删除应考虑证据价值、未来用途和可恢复性。
3. 链接数量不是目标，关系清晰且能帮助调用才是目标。
