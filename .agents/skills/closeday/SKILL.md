# Close Day: Daily Review

回顾一天的工作，总结进展、捕获经验教训、识别未完成事项、判断哪些经验需要沉淀为系统规则，并规划明日延续。

---

## 工作流程

### Step 1: 读取核心上下文

首先读取 `AGENTS.md` 理解仓库结构和写作规则。

先执行 `date` 命令核对当前日期，再据此定位今日 Daily Note 与 vault 路径（日期不得凭记忆推断）。

### Step 2: 读取今日 Daily Note

从 `01_Daily/` 目录读取今日日期对应的 `.md` 文件：
- 文件名格式：`YYYY-MM-DD.md`
- 读取模板参考：`Templates/Daily_Note.md`（如果存在）

### Step 3: 读取正式任务来源

读取：

- `05_Tasks/Tasks.md`
- 今日重点关联的项目任务源
- 项目统一读取 `Project.md` 中的“下一步”和 Backlog
- 不读取 `06_Archive/Project_Migrations/` 中的旧任务文件作为当前状态

### Step 4: 分析并生成回顾

基于今日 Daily Note 的内容，分析：

- **今日完成**：从“今日记录”和正式任务源确认完成的事项
- **今日推进**：即使未完成但有推进的事项
- **新想法**：标记为 `[想法]` 的洞察或明确表达的新认识
- **未完成事项**：今日重点中尚未完成、且在正式来源仍为开放状态的任务
- **可延续内容**：仍应保留在 Tasks 或项目任务源的内容
- **系统写回建议**：根据今日新增内容、项目推进、协作流程和反复出现的问题，判断是否有规则、流程、命名、写作规范或工作原则值得写回 `System/`

不要把未完成事项复制到第二天的 Daily。需要调整状态时，回到正式任务来源更新（跨日处理见常见问题 Q3）。

### Step 5: 生成一日总结

生成一句话的今日总结（适合作为今日记录的结尾）。

### Step 6: 判断系统写回建议

基于今日更新，判断哪些内容可能需要写回系统层。重点关注：

- 新出现且未来会反复复用的工作流程
- 对 AI 协作方式有约束作用的新规则
- 命名、目录结构、模板、链接维护等可标准化的规范
- 写作风格、输出格式、知识入库标准的调整
- 本次任务中出现的执行偏差或验证经验

不要把一次性项目进展、临时任务、普通总结写入系统建议。若没有值得沉淀的内容，应明确写“暂无”。

## 写回规则

- **默认只读**：仅展示回顾内容，不自动写入
- **确认后写入**：用户明确确认后，才更新今日 Daily Note
- 优先更新“今日记录”和“一句话总结”，不要另造平行的回顾状态区
- 任务完成状态回到 Tasks 或项目任务源更新
- **系统写回建议只作为建议**：除非用户明确要求“写回系统/更新系统规则”，否则不要自动修改 `System/`

---

## 通用规则

- **Always read AGENTS.md first** — 首先读取仓库导航规则和写作规范

---

## 输出要求

- 突出“完成”而非“忙碌”
- 洞察和思考要简洁可复用
- 系统写回建议要克制，只记录长期可复用的规则，不记录一次性项目进展
- 明日延续要具体可执行

---

## 常见问题处理

**Q: 如果今日 Daily Note 不存在怎么办？**
A: 提示用户先创建今日 Daily Note，或基于模板自动创建

**Q: 如果今日内容很少怎么办？**
A: 诚实输出，不强求"充实"。少量进展也是进展

**Q: 如何判断哪些应该延续至明日？**
A: 确认任务仍有效后，将其保留或调整在 Tasks、项目下一步或项目 Backlog 中；明天再次选择时再写入“今日重点”。未完成事项的跨日处理见 Step 4。
